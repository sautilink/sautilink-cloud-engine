Web + Telegram

Two interfaces. One diagnostic engine.

The goal is not to duplicate every screen. Each channel gets the experience it is best at while sharing the same analyzer contracts underneath.

Web workspace

Primary surface for deeper work and the largest feature set.

  • Best for: detailed reports, visual exploration, long findings and multi-tool workflows.
  • More than bot: future compare, exports, saved workspaces and richer result controls.

Telegram companion

Fast access when a full web session is unnecessary.

  • Best for: quick checks, guided prompts, reruns and lightweight status.
  • Shared truth: the same Cloud Engine analyzer APIs power both channels.
Planned bridge: signed handoff IDs will let a result started in one channel continue in the other without placing raw targets, secrets or internal architecture in callback data.

Shared engine

One API contract underneath everything.

The website and Telegram companion remain clients of the same Cloud Engine analyzers rather than becoming separate products with conflicting results.

Simple service health check used by this workspace to confirm that the engine is responding.
